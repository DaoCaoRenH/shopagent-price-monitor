# 前端组件与业务分层

## 本次设计约定

- 使用者与任务：本机用户搜索商品、确认规格，查看监控价格与提醒。
- 信息顺序：商品/价格与当前状态优先，其次是采样依据，再提供加入监控、检查或生成建议的操作。
- 数据：只显示后端返回的目录、快照和模拟记录；默认虚构演示目录始终明确标识。
- 布局：桌面为侧栏导航与工作区，价格详情为曲线与操作区；手机为顶部导航、纵向内容与可滚动弹窗。
- 视觉：沿用绿色主操作、浅色背景、价格数字和现有间距/圆角，继续使用现有 SVG 图标。
- 特色：每个商品规格独立的价格曲线，明确区分快照与模拟记录。
- 主要风险：异步响应覆盖后来的商品/页面，以及自动刷新破坏表单输入；用请求序号、取消和 Vue 的局部更新验证。

```text
桌面                              手机
导航 | 页面标题与状态             导航
     | 搜索 / 列表 / 曲线          标题与状态
     | 证据与操作                 主任务
                                  采样依据与操作
```

## 职责

`views/` 组合页面；`components/` 显示数据、收集输入并发出事件；
`composables/` 管理异步流程与状态；`api/` 处理 HTTP/NDJSON；
`types/` 定义前后端交换数据。组件不直接调用 Fetch。

金额比较、新低判定、规格报价、价格模拟和持久化继续由 Python 后端负责。

## 目录与使用方式

```text
frontend/src/
  views/              # 搜索、监控列表/详情、搜索历史、提醒、数据与设置
  components/
    common/           # 图标、提示、空状态、原生弹窗、Toast
    layout/           # 侧栏、工作区和概况
    products/         # 共用候选卡、商品详情、规格与模拟配置
    search/           # 搜索表单、真实进度、步骤记录
    watches/          # 价格曲线、模拟状态、建议、提醒
    settings/         # 生效配置摘要和搜索预算
  composables/        # 业务状态、请求生命周期、操作流程
  api/                # HTTP 错误、NDJSON 分帧、业务接口
  types/              # Product / Watch / Advice / ModelSettings 等契约
  lib/                # 请求序号、格式化、时间轴坐标
```

依赖方向是 `views/components → composables → api → FastAPI`。通用展示组件直接接收 props 并发出事件；搜索和商品弹窗等流程入口可以调用对应 composable。`api` 不引用页面或 Vue 状态；组件不直接使用 fetch。这里只调整浏览器端的组织方式，服务端的规则和评分不迁移到前端。

例如修改“加入监控”：按钮与详情布局在 `ProductDialog.vue`，当前商品/规格/报价以及提交状态在 `useProductSelection.ts`，创建请求在 `api/watches.ts`，真正的规格校验与落库仍由后端负责。修改文案无需动接口，修改网络错误处理无需逐页修改。

## 状态与异步边界

- 搜索状态、最终候选与提交时的原始描述由 `useSearch` 共享保存。切页再回来、加入监控后仍能继续比较；输入框后续修改不改变已返回候选绑定的原需求。历史候选绑定其当次需求。
- `LatestRequest` 同时使用 AbortController 和递增序号。取消只负责减少无用请求，序号负责阻止已经返回或不响应取消的旧结果写入新页面。商品详情、规格报价、历史列表/详情和价格历史分别隔离。
- 改变规格后立即清空旧报价。缺少完整规格、报价等待/失败或正在提交时禁止创建；切换商品和关闭弹窗会撤销旧详情与报价。提交期间禁止重复创建及关闭。
- 进度按 `step_id` 更新同一步，按 `sequence` 忽略重复/过时事件，回退时将未结束步骤标为中止。只收到完整 NDJSON `result` 才接收结果；跨字节 UTF-8、截断、后端错误和用户取消分别处理。运行中和筛选未完成不展示虚构完成百分比。
- 提醒、模型设置、导入、监控操作各自有 pending/error，失败后恢复操作能力。模型配置只提交可编辑字段，不回传 GET 的服务器元信息；密钥仅停留于当前草稿，保存/离开后清除，不写浏览器存储。
- 建议按监控 ID 保存偏好与结果；价格历史版本、监控状态、模型版本、偏好或有效期变化后显示“建议待更新”。金额比较与结论证据由后端提供。
- 每 10 秒局部刷新概况；页面隐藏、弹窗打开或表单正在输入时跳过。Vue 更新响应式节点，不重建整个 DOM，因此刷新不会重置手动报价、预算和未提交配置。离开价格详情会取消其读取请求。
- 弹窗使用原生 dialog 管理焦点约束，关闭后回到原入口；支持 Esc、键盘操作、skip link 和减少动画偏好。旧 `#monitor`、`#watch/<id>` 等书签可继续打开。

## 开发与分发

使用 Node 22.12+ 或 24+：在 `frontend/` 执行 `npm ci`、`npm test` 和 `npm run build`。构建同时运行 TypeScript 检查，并输出到 Python 包的 `app/static/`。生成文件提交到 Git，安装 wheel 后直接使用 Python 启动，无需 Node。

开发模式执行 `npm run dev`，它将 `/api` 转发到 `127.0.0.1:8092`；另开终端使用项目虚拟环境运行 `python -m shopagent_monitor --port 8092 --data-dir .shopagent/frontend-dev`。真实配置与数据库不进入前端工程。

CI 重新构建并比较已提交的静态目录，执行前后端测试、源码包/wheel 构建以及从临时目录检查打包网页资源。`MANIFEST.in` 只收录明确的前端源码与配置，不包含 node_modules。

## 本机验收记录（2026-11-03）

使用 Windows、Python 3.12、Node 24 验证：21 项 Vitest、111 项 Python unittest、TypeScript/Vite 生产构建和 Ruff 均通过。全新虚拟环境安装 wheel 后，从临时工作目录验证网页 JS/CSS 和第三方许可证、12 个演示商品、搜索、规格报价、创建监控、价格导入、新低提醒、规则建议与重启持久化均通过。源码包检查不包含 node_modules、凭据或用户数据库。

真实浏览器验收使用独立演示数据库，预览端口为 8092，没有改动原 8090 服务的数据。检查了 `390×844`、`768×1024`、`1440×900`、`1920×1080`、`2560×1080` 五种视口，均未出现横向溢出；手机搜索入口、规格弹窗和详情页可操作。弹窗 Esc 关闭后焦点回到原入口，删除确认可取消。

交互覆盖目录搜索、候选保留、历史继续配置、快照导入、提醒标为已读、具体连接错误、搜索操作上限保存、建议过期与监控暂停。固定 `new_lows` 回放按 30 秒一步实际采集 8 条报价，产生 3 次新低提醒并自动停止；重新回放创建独立监控，保留上一轮记录。受控模型通过真实 HTTP/NDJSON 验证了流式步骤、工具有限补正后的部分候选、停止接收与操作恢复；无外部供应商在线质量测试。预览页与受控模型页的浏览器控制台未捕获警告或错误。

本次重构的待验证范围是实际外部模型服务的延迟、连接行为与筛选质量；受控响应只验证前端协议和状态流程。GitHub CI 需在推送后另行确认。
